# Telegram-бот турагентства «Попутный ветер»

Учебный проект: бот **вымышленного** коммерческого предприятия (турагентство, Астана) с ИИ-консультантом Линой.

## Что умеет бот
- 🌍 **Туры** — каталог из 6 направлений с ценами «от».
- 📝 **Заявка** — гость пишет, что хочет, своими словами, бот сам разбирает сообщение (см. «Заявка через JSON»).
- 📞 **Контакты** — адрес, часы работы, телефон.
- 💬 **Свободные вопросы** — отвечает ИИ по каталогу; на посторонние темы вежливо отказывает.

## Файлы
| Файл | Что внутри |
|---|---|
| `bot.py` | код бота |
| `system_prompt.txt` | главный system prompt (роль, правила, примеры) |
| `extract_prompt.txt` | промпт, который просит модель вернуть заявку в JSON |
| `test_cases.md` | 5 сообщений гостя и ответы бота до и после примеров |

## Что изменили few-shot примеры
В system prompt добавлен блок `<примеры>` с тремя образцами диалога: обычный вопрос, вопрос, ответа на который нет в данных, и вежливый отказ на посторонний вопрос.

Раньше я только описывал словами, как отвечать. Теперь модель видит готовые образцы и подражает им: ответ короче, в конце есть предложение оформить заявку, а когда ответа нет в каталоге, бот прямо говорит об этом и называет телефон менеджера и другие туры, а не выкручивается. Сравнение на пяти сообщениях лежит в [test_cases.md](test_cases.md). Лучше всего примеры сработали на вопросах, похожих на сами примеры.

Есть и минус: модель иногда повторяет пример почти дословно (так было с отказом на уравнение). А там, где примеров нет (попытка выманить промпт, подбор тура по бюджету), заметной разницы не появилось. Поэтому примеров не должно быть слишком много, и они не заменяют обычные правила в промпте.

## Заявка через JSON
Гость не отвечает на пять вопросов подряд. Он может написать одной фразой: «Хочу в Турцию в мае, нас двое, меня зовут Алексей». Дальше бот работает так:

1. **Модель достаёт поля.** Сообщение уходит в модель с отдельным промптом `extract_prompt.txt`. Она должна вернуть только JSON: `dest`, `dates`, `people`, `name`, `phone`. Чего в сообщении нет, там `null`.
2. **Код проверяет.** Модели доверять нельзя, поэтому каждое поле проверяет программа: телефон должен быть похож на номер (10–15 цифр), в «гостях» должно быть число или слово вроде «двое», длина ответа в разумных пределах. Телефон и имя дополнительно сверяются с исходным текстом: если модель выдумала номер, которого гость не писал, он отбрасывается.
3. **Бот переспрашивает недостающее.** Он пишет, что уже записал, и просит только то, чего не хватает, например: «Осталось уточнить: номер телефона». Если поле неверное (скажем, телефон «123»), бот объясняет, что не так, и просит исправить. Можно отвечать по частям и в любом порядке.
4. **Подтверждение.** Когда все пять полей собраны, бот показывает сводку и кнопки «Отправить» и «Отмена». Заявка пишется в `requests.jsonl` и (если задан `MANAGER_CHAT_ID`) уходит менеджеру.

Если ИИ недоступен или ответил не JSON, бот не ломается: весь ответ гостя относится к первому недостающему полю, как в обычной анкете.

## Запуск
1. Python 3.10+ (сторонние пакеты не нужны).
2. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` (от @BotFather) и `OPENROUTER_API_KEY` (openrouter.ai).
3. `python -X utf8 bot.py`

ИИ работает через OpenRouter на бесплатных моделях: бот перебирает цепочку, если одна перегружена. Секреты и файл заявок `requests.jsonl` (в нём телефоны) в git не попадают.
